## 4. 根因定位

### 直接原因

模型返回的 `SecurityGraphDecision.NextIntents[].RequiredEvidence` 字段类型不匹配：

- **代码期望**：`[]string`（字符串数组）
- **模型实际返回**：数字数组（如 `[1704, 1705]`，即 evidence ID）

这导致 `json.Unmarshal` 失败，整个 graph reasoning 决策（包括 Facts、Findings、NextIntents）全部被丢弃。

### 代码位置

文件：`backend/internal/service/model_runtime_service.go`

相关类型定义：
```go
type SecurityGraphIntentSuggestion struct {
    Title            string   `json:"title"`
    Objective        string   `json:"objective"`
    IntentType       string   `json:"intent_type"`
    RequiredEvidence []string `json:"required_evidence"`  // ← 这里期望 []string
}
```

模型返回类似：
```json
{
  "next_intents": [{
    "title": "...",
    "objective": "...",
    "intent_type": "collect_evidence",
    "required_evidence": [1704, 1705]  // ← 模型返回了 []int
  }]
}
```

### 解析函数位置

`parseSecurityGraphDecisionOutput` 函数在解析时，因为 `required_evidence` 字段类型不匹配，整个 JSON unmarshal 失败，返回 error，导致：
1. `reasonOverSecurityGraph` 返回空 suggestions + error
2. `applyGraphDecision` 不被调用
3. 模型产生的 Findings 和 NextIntents 全部丢失
4. 系统回退到 `deepCodeAuditInBatches`，但大部分 batch 也失败了（22/26 失败）

### 为什么 Task 49 成功但 Task 52 失败？

Task 49 的 graph reasoning 也失败了（同样的 context deadline exceeded 错误），但它的 `deepCodeAuditInBatches` 大部分成功了（21/24 成功）。

Task 52 的 `deepCodeAuditInBatches` 大部分失败了（22/26 失败，只有 4 个成功）。

**差异原因推测**：Task 52 上传的代码可能更大/更复杂，导致每个 batch 的 prompt 更长，模型超时或返回格式不稳定。

## 8. 最小修复建议（不开始修复，仅列出）

### P0：修复 SecurityGraphIntentSuggestion.RequiredEvidence 类型兼容

将 `RequiredEvidence []string` 改为能同时接受 `[]string` 和 `[]int` 的灵活解析。或者使用 `json.RawMessage` + 自定义 unmarshal。

**这是唯一真正的根因修复。** 修复后，模型返回的 graph reasoning 结果（包含 findings 和 next_intents）就不会被丢弃了。

### P1：增加模型输出容错

当 JSON 解析失败时，尝试用更宽松的方式解析（如忽略类型不匹配的字段，只提取能解析的部分）。

### P2：记录模型 raw response

当前系统不记录模型的原始响应，导致调试困难。建议在 audit_events 中记录脱敏后的模型响应摘要。

### 不需要做的事

- ❌ 不需要改 reasonPasses
- ❌ 不需要改 codeAuditReasoningEffort（之前的修复是正确的但不是根因）
- ❌ 不需要加确定性 Finding 生成器（模型本身能发现漏洞，问题是输出解析失败）
- ❌ 不需要改 code_search/code_slice（它们工作正常）
- ❌ 不需要改 Contract（它工作正常）

## 9. 总结

**系统不是"发现不了漏洞"，而是"模型发现了但系统解析失败把结果丢了"。**

根因是一个类型不匹配的 JSON 解析 bug：`SecurityGraphIntentSuggestion.RequiredEvidence` 期望 `[]string`，模型返回 `[]int`。修复这一个点，graph reasoning 的结果就能正确传递到 Finding 创建流程。
